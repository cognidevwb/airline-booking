Scope and limitations

  • Targets asked for: . Read from: permutations.json — value classes per column; datamodel.json — declared constraints, including the unique key; schema.json — the declared relation count.
  • Values are labelled and the locale is en-GB. Generated by the CogniDev generate-test-data playbook. No value here is derived from production data.
  • CSV writes SQL NULL as an empty unquoted field and the empty string as "". That is the only distinction CSV can carry.
  • A BIT column takes one spelling per format, and only one: 1 / 0 in SQL and CSV, which is what a bit column loads from; JSON's own true / false. Whatever a value class or a declared DEFAULT was written as, the output is uniform.
  • A DATE column carries a date and no time. Every other date type keeps its time — the distinction is read from the declared type name, not from the base type.
  • A length boundary binds EXACTLY the declared width, and is shaped to the column's own kind at that width: an address for an email column, whole name parts for a person, whole words for free text, a value from the declared vocabulary where one is that long. Where nothing states what the column holds it takes a generated CODE rather than a phrase cut mid-word — an obviously synthetic token beats a value that pretends to be content. Negative records keep the structural value verbatim: their job is to be rejected, and reshaping them would change the rule each one breaks.
  • Negative rows are written to their own SQL script. By construction they do not load into a schema with its constraints enabled.
