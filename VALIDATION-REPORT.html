Basis and limitations

Basis. Each condition is evaluated by reading a record produced by this run — a file, a count, an exit status — and comparing it with the condition as stated. No result is entered by hand, and no condition passes because it was not examined: where the record is missing, the result is recorded as not verified.

Confidence. A satisfied condition establishes that the stated property held for this run, on this input, at the time the record was written. It is evidence about what was examined and nothing more. It does not establish that the schedule is complete, that the output is fit for a particular purpose, or that properties nobody listed are sound.

Limitations. The schedule is written by the playbook author and is not exhaustive. Figures derived from a language model vary between runs on identical input and are stated as findings of this run, not as properties of the system. Reading the output remains necessary; this record is not a substitute for it.
